# ADR-001: URL取込のSSRF防御をIPピン留め方式にする

## 日付
2026-06-11

## 状態
Accepted

## 状況
URL取込が製品唯一のネットワーク経路。初版は `getaddrinfo` で名前解決→プライベートIPを拒否した後、`urllib` が接続時に**独立して再解決**していた。検査時と接続時でDNS応答を変えられると(DNSリバインディング/TOCTOU)、検査=公開IP・接続=`169.254.169.254`(クラウドメタデータ)や`127.0.0.1`を返して防御を迂回できる。自己ホスト前提でもクラウドVM上運用を想定すると看過できない。

## 決定
名前解決を1回だけ行い、検査を通過したIPリテラルに**ピン留め**して接続する。再解決を発生させない。

## 根拠
- 検査したIPと接続するIPが同一になり、両時点間のリバインディング窓が消える。
- stdlibのみで実現可能(`http.client.HTTPConnection.connect` を override してピンIPへ `create_connection`)。
- HTTPSは接続先=ピンIP・SNI/証明書検証=元ホスト名(`wrap_socket(server_hostname=host)`)で両立。
- リダイレクトは手動追跡し、各ホップで再検証+再ピン留め。

## 却下した代替案
- **再検証のみ強化**: 接続時の再解決が残る限りリバインディングを防げない。却下。
- **requests + 外部SSRFライブラリ**: 依存ゼロ方針(C6)に反する。却下。
- **IPアドレス直接指定のみ許可**: 通常のURL取込が不便。却下。

## 結果
`test_ssrf_fetch_pins_validated_ip`(接続先がピンIPリテラルであること)と `test_ssrf_rebinding_to_private_blocked`(取込時にプライベート解決を拒否)で回帰を固定。
