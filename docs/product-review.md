# Shoin プロダクトレビュー — 長所・短所・改善点 (2026-06-11)

v0.1.0 全コード(約3,400行 + UI 590行)・テスト79件・ドキュメント一式の精査結果。
「実装済み」の改善は v0.1.1 に収録。

## 長所 (維持すべき差別化資産)

1. **引用の機械検証** — 競合(Open Notebook / SurfSense / InsightsLM)に無い核。
   結合形式 `[S1, S2]`・全角・S空白まで正規化して範囲外番号を100%検出し、
   さらに v0.1.3 で各引用文とソース本文の字句照合による誤帰属検出を追加
   (`citation.py`、合成テストでDoD検証済み)。
2. **依存最小・単一プロセス** — ランタイム依存は pypdf のみ。stdlib HTTPサーバ +
   単一HTML(ビルド工程なし)。`pip install shoin` だけで動く配布性は本物。
3. **graceful degradation が一級市民** — LLM不在→検索のみ、埋め込み不在→BM25のみ、
   が全てテストで担保。8GB RAM級PCという設計制約に正直。
4. **SSRF防御の質** — IPピン留めでDNSリバインディング(TOCTOU)まで遮断 (ADR-001)。
   リダイレクト毎に再検証。ローカルツールとしては過剰なほど堅牢。
5. **日本語一次設計** — FTS5 trigram + CJK対応チャンク/トークン推定 + LIKEフォール
   バック(2文字語)。cp932フォールバックデコードまで配慮。
6. **工学的衛生** — migration機構、安定エラーコード体系、ruff/mypy --strict ゼロ、
   カバレッジ86%、SBOM、STRIDE文書。v0.1.0としては異例の水準。
7. **UI** — XSS安全(textContentのみ)、i18n、WCAG配慮、蔵書印メタファの一貫した意匠。

## 短所と改善点

### 実装済み (v0.1.1)

| # | 問題 | 対応 |
|---|------|------|
| 1 | **追問が成立しない**: 会話履歴をDBに保存しながらプロンプトに渡しておらず、「それを詳しく」が通らない。NotebookLM代替を名乗る上で最大のUXギャップ | 直近6メッセージ(各160トークンに切詰め)をプロンプトに同梱。履歴中の `[S番号]` は文脈毎に番号が変わるため除去 (`qa.history_messages`) |
| 2 | **ローカルUIへのCSRF/DNSリバインディング**: 悪意あるWebページから `no-cors` POST や リバインドしたホスト名経由で 127.0.0.1:7440 のAPIを叩けた(Content-Type非検査のため `text/plain` ボディでも通る) | Hostヘッダを 127.0.0.1/localhost/::1 に限定、状態変更リクエストのクロスサイトOriginを403拒否 (`server._reject_cross_site`) |
| 3 | **UI操作のたびにLLM呼び出し**: ノートブックを開く度・ノート追加の度に推奨質問の生成が走る(軽量PCで体感数十秒の無駄) | ソースID集合をフィンガープリントにしたサーバ側キャッシュ |
| 4 | スレッド並行書込みで即時 SQLITE_BUSY の可能性 (ThreadingHTTPServer + リクエスト毎Store) | `PRAGMA busy_timeout=5000` |
| 5 | 存在しないソースIDの `/text` が200+空配列 | 404 (`SOURCE_NOT_FOUND`) |
| 6 | サイズ超過JSONボディをdrainせず応答(接続リセットでエラーが届かない恐れ) | `_drain` してから400 |
| 7 | `rename_notebook` が空文字名を許容(作成時と非対称) | 検証追加 |
| 8 | clickjacking 対策ヘッダ欠如 | CSP `frame-ancestors 'none'` + `X-Frame-Options: DENY` |

### 実装済み (v0.1.2)

| # | 問題 | 対応 |
|---|------|------|
| 9 | **追問時の検索クエリ**: 履歴はLLMに渡るが検索は現在質問のみで空振りしうる | 30文字未満の質問に直前ユーザー発言を連結して検索 (`qa.expand_query`) |
| 10 | **引用ジャンプのタイトル衝突**: 同名ソース複数で誤ジャンプ | `citation_report.source_id_map` を追加しUIは source_id で直接ジャンプ(旧レポートはタイトル照合にフォールバック) |
| 11 | **notebook rename のAPI/UI露出**: store層のみで到達不能 | `PATCH /api/notebooks/{id}` + サイドバー✎ボタン |
| 12 | **チャット履歴クリア機能なし**: messages が無限蓄積 | `DELETE /api/notebooks/{id}/messages` + 文机クリアボタン |

### 実装済み (v0.1.3) — ソクラテス問答による中核改善

| # | 問題 | 対応 |
|---|------|------|
| 13 | **「引用検証」の看板と実態の乖離**: `validate_citations` は引用番号が範囲内(1..n)かのみ検査。実在ソースへの**誤帰属**(citation hallucinationの主形態)は素通り。「空は緑だ[S1]」もS1が在れば通過していた | `verify_grounding`: 引用付き各文を引用先ソース本文と文字bigramで照合し、ほぼ無関係なら weak フラグ。`weak`/`grounding` を citation_report に追加。依存ゼロ・LLM不要。UIは破線・琥珀の蔵書印 + バッジで提示 |

> 補足: 統合テストで閾値0.12が共通コピュラbigram「ある」単独を許し偽陰性を生むことを発見→CJK向けに0.30へ較正、回帰テスト化。字句シグナルゆえ助言的(言い換えで偽陽性の可能性)であり、ハードエラーではなく警告として扱う設計。

### 未実装 (今後の検討課題、優先度順)

1. **埋め込みモデル変更の検出**: `SHOIN_EMBED_MODEL` を変えても旧ベクトルが残る。
   次元不一致は cosine=0 で静かに無害化されるが、同次元別モデルは検出不能。
   chunks にモデル名カラムを追加するmigrationが筋(スキーマ変更のためv0.2)。
2. **Studioの代表チャンク**: 各ソース先頭3チャンク固定のため長文ソースの後半が
   年表/マインドマップに反映されない。セクション見出し抽出 or 等間隔サンプリング。
3. **SSE切断時の永続化**: クライアント切断で書きかけの assistant メッセージが
   保存されない(BrokenPipeError)。途中結果の保存 + 再描画を検討。
4. **未引用の事実文の検出**: grounding は引用「付き」文の根拠を見るが、引用が
   一切ない事実文(無出典の断定)は素通り。文単位の引用被覆率の導入を検討。
5. **国際化の残り**: CLI出力・サーバ起動メッセージは日本語固定(`SHOIN_LANG` はUIのみ)。

## 結論

設計判断(軽量・検証・日本語の3点集中)は正しく、出荷水準。v0.1.1〜v0.1.2で
マルチターン・CSRF・改名/クリア等のUXとセキュリティ穴を塞いだ。v0.1.3では
ソクラテス問答により**中核の差別化(引用検証)が範囲チェックに留まり誤帰属を
見ていない**という最大の乖離を特定し、依存ゼロの根拠検証で埋めた。これにより
看板「citation hallucination対策」が範囲外番号と誤帰属の両方を指すようになった。
