# Shoin プロダクトレビュー — 長所・短所・改善点 (2026-06-13)

v0.1.0 全コード(約3,400行 + UI 590行)・テスト79件・ドキュメント一式の精査結果。
「実装済み」の改善は v0.1.1 に収録。

## 長所 (維持すべき差別化資産)

1. **引用の機械検証** — 競合(Open Notebook / SurfSense / InsightsLM)に無い核。
   結合形式 `[S1, S2]`・全角・S空白まで正規化して範囲外番号を100%検出し、
   さらに v0.1.3 で各引用文とソース本文の字句照合による誤帰属検出を追加
   (`citation.py`、合成テストでDoD検証済み)。
2. **依存最小・単一プロセス** — ランタイム依存は pypdf のみ。stdlib HTTPサーバ +
   単一HTML(ビルド工程なし)。`pip install shoin` だけで動く配布性は本物。
3. **graceful degradation が一級市民** — LLM不在→検索のみ、埋め込み不在→BM25のみ、
   が全てテストで担保。8GB RAM級PCという設計制約に正直。
4. **SSRF防御の質** — IPピン留めでDNSリバインディング(TOCTOU)まで遮断 (ADR-001)。
   リダイレクト毎に再検証。ローカルツールとしては過剰なほど堅牢。
5. **日本語一次設計** — FTS5 trigram + CJK対応チャンク/トークン推定 + LIKEフォール
   バック(2文字語)。cp932フォールバックデコードまで配慮。
6. **工学的衛生** — migration機構、安定エラーコード体系、ruff/mypy --strict ゼロ、
   カバレッジ86%、SBOM、STRIDE文書。v0.1.0としては異例の水準。
7. **UI** — XSS安全(textContentのみ)、i18n、WCAG配慮、蔵書印メタファの一貫した意匠。

## 短所と改善点

### 実装済み (v0.1.3) — ソクラテス問答による中核改善

| # | 問題 | 対応 |
|---|------|------|
| 13 | **「引用検証」の看板と実態の乖離**: `validate_citations` は引用番号が範囲内(1..n)かのみ検査。実在ソースへの**誤帰属**(citation hallucinationの主形態)は素通り。「空は緑だ[S1]」もS1が在れば通過していた | `verify_grounding`: 引用付き各文を引用先ソース本文と文字bigramで照合し、ほぼ無関係なら weak フラグ。`weak`/`grounding` を citation_report に追加。依存ゼロ・LLM不要。UIは破線・琥珀の蔵書印 + バッジで提示 |

> 補足: 統合テストで閾値0.12が共通コピュラbigram「ある」単独を許し偽陰性を生むことを発見→CJK向けに0.30へ較正、回帰テスト化。字句シグナルゆえ助言的(言い換えで偽陽性の可能性)であり、ハードエラーではなく警告として扱う設計。

### 実装済み (v0.1.6) — 第6ラウンド: graceful degradation の未完成を指摘

| # | 問題 | 対応 |
|---|------|------|
| 17 | **SSE 切断が会話履歴を破壊**: 長所 #3「graceful degradation が一級市民」と主張しながら、SSE ストリーム中の `BrokenPipeError`(ブラウザタブ閉じ等)でユーザーメッセージだけが DB に残りアシスタントメッセージが未保存のまま終了していた。次ターンで `history_messages` がその孤立ユーザーターンをプロンプトに含め LLM に `user→user` という意味的に不正な履歴を渡し、前の質問の回答を補完しようとする可能性があった | ① `_h_ask_sse` で `BrokenPipeError` をキャッチし、部分生成内容でもアシスタントメッセージを保存 ② `history_messages` が末尾のユーザーターンをトリムする防御コードを追加。「graceful degradation」は可用性だけでなく一貫性にも適用されるべき |
| 18 | **`suggest_questions` が `か。` 終わりの質問を無音で除外**: `endswith("か")` が `か。` を見逃す。軽量ローカル LLM は「装飾なし」指示に反して文末 `。` を付ける場合があり、有効な質問提案が無音で失われていた。失われた提案はユーザーに見えないため、不正な提案を受け入れるより有害 | 末尾句読点を除去してから `endswith("か")` を判定するよう修正 |

> 教訓: graceful degradation の宣言は、ネットワーク層と DB 一貫性の両方をカバーして初めて完全になる。一方だけを処理すると、もう一方が障害時に状態を破壊し、その破壊が次のリクエストでサイレントな誤動作として表面化する。

### 実装済み (v0.1.5) — 第5ラウンド: v0.1.4 の残留矛盾を除去

| # | 問題 | 対応 |
|---|------|------|
| 15 | **`grounding` スコアが v0.1.4 の設計原則と矛盾**: v0.1.4 で「判定不能なら沈黙する」と定めたにもかかわらず、全引用文が同義語言い換え(字句重なり低く判定不能)の場合に `grounding=0.0` を出力していた。これは「グラウンディングなし」という**負の断言**であり、設計が明示的に回避すると決めた主張そのもの。なお `cited=0`(引用なし)では `1.0` を返すという非対称性も存在し、同じく「字句的に確認できなかった」状況を正反対のスコアで表現していた | `grounding` フィールドを `CitationReport` から削除。`verify_grounding` の戻り値を `(confirmed, misattributed)` の2値に変更。`confirmed` と `misattributed` のリストが完全で正直なシグナルであり、集約スコアは情報を加えず誤解を招くのみ |
| 16 | **`suggest_questions` が LLM 障害時に graceful degradation しない**: Q&A 等の他の LLM 連携パスは全て `LLMError` をキャッチして安全に縮退するが、`suggest_questions` だけは例外を伝播させて 502 エラーを返していた。推奨質問はベストエフォートの補助機能であり、LLM 障害がエラー応答になるのは設計原則「graceful degradation が一級市民」と矛盾 | `suggest_questions` 内で `LLMError` をキャッチして `[]` を返すよう修正。空ノートブックの場合と同じ縮退 |

> 教訓: 前のラウンドの修正が導入した原則を、その修正自身が破っていた。v0.1.4の「沈黙が知的に誠実」という原則は、`grounding=0.0` という数値が設計上存在してはならない主張をしていたことで自己矛盾を抱えていた。修正の完成は、修正が生んだ原則に対して修正自身を問い直すことで初めて達成される。

### 実装済み (v0.1.4) — 第4ラウンド: 自分の前回改善への批判

| # | 問題 | 対応 |
|---|------|------|
| 14 | **v0.1.3 の根拠検証が正しい回答を誤って咎める**: 実測で「収益が伸びた[S1]」/ソース「売上高は増加した」のような**同義語による正しい言い換え**(字句重なり0)を、誤帰属(同じく0)と区別できず weak と誤判定。信頼を築く旗艦機能が偽陽性を出すのは無検出より有害 | 字句信号の非対称性(高重なり=確実な正の証拠 / 低重なり=判定不能)を踏まえ精度優先へ再設計。`confirmed`(裏付けあり)と `misattributed`(別ソースに強一致=番号取り違え、高精度)のみ提示し、判定不能は沈黙。`weak`→`confirmed`+`misattributed` に置換 |

> 教訓: 字句グラウンディングは同義語を解決できない以上、低重なりを「根拠なし」と断罪してはならない。確信できる主張(裏付けの存在/番号の取り違え)のみ述べ、それ以外は沈黙するのが知的に誠実。

## 結論

設計判断(軽量・検証・日本語の3点集中)は正しく、出荷水準。v0.1.1〜v0.1.2で
マルチターン・CSRF・改名/クリア等のUXとセキュリティ穴を塞いだ。v0.1.3で
中核の引用検証が範囲チェックに留まる乖離を字句グラウンディングで埋め、
v0.1.4では**その実装自身を問い直し**、字句信号では同義語言い換えと誤帰属を
区別できない以上「根拠なし」と断罪するのは偽陽性で信頼を損なうと結論。
v0.1.5ではさらに**v0.1.4が導入した設計原則に v0.1.4 自身が違反していた**ことを
指摘し除去した。「沈黙が知的に誠実」と定めた直後の実装が `grounding=0.0`
という負の断言を出し続けていたこと、`suggest_questions` だけが graceful
degradation の例外として残っていたことが今回の発見。各ラウンドの本質は
一貫して同じ問いに収斂する——「看板の主張と実装は本当に一致しているか」。
